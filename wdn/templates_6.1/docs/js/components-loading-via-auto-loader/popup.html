Popup - Auto-Loader

The popup component, otherwise known as a tooltip, is a second of content that can pop up when a button is clicked or hovered. This is great for some added details that may clutter the page if it was always displayed.

Warning! This component is needed for the base page templates so if the visit, apply, give buttons are not working correctly you may have changed the default Popup component configuration in the auto-loader.

This component inherits a lot of its functionality, keyboard interactions, and events from the toggle button component.

The auto-loader references /wdn/templates_6.1/js/plugins/plugin.popup.js by default. That plugin will be looking for .dcf-popup:not(.dcf-popup-initialized) as the trigger to load the components code dependencies and initialize the component.

To create the component you can add the class dcf-popup class onto a div element. This div element will also need a button as the toggle for the popup and another div that will become the content of the popup. These popups are designed to have basically no styles applied to them to give as much flexibility to the developer as possible.

          <div id="test" class="dcf-popup">
            <button class="dcf-btn dcf-btn-primary dcf-btn-toggle-popup">Open Popup</button>
            <!-- There are lots of additional styling classes applied to .dcf-popup-content in this example -->
            <div class="dcf-popup-content unl-bg-cerulean unl-cream dcf-rounded dcf-w-100% dcf-p-3" hidden>
              Lorem ipsum dolor sit amet, consectetur adipiscing elit. Aenean luctus hendrerit urna quis pellentesque. Aenean tempor est commodo nisi gravida interdum.
            </div>
          </div>

The div.dcf-popup element will need an id, and if it does not have id then a randomly generated one will be assigned to it. Once initialized the class dcf-popup-initialized will be added to the div.dcf-popup element and it will remove the hidden attribute from the it. The class instance will also add itself to the window.UNL.classes object so you can use getClassInstance to get a reference of the class instance.

Options

The popup component has a couple options associated with its functionality.

Hover

The first option is the option to hover over the button to open the popup. You can enable this option by adding data-hover="true" to the div.dcf-popup element.

Position & Alignment

The position and alignment of the popup is relative to the toggle button. As of now these values are dumb and do not change based on where in the viewport the button is located so there is a chance that the popup content might overflow off the side of the viewport. Position is referring to which side of the button the popup will be located when opened, and alignment is referring to the alignment of the popup on that side. To change the position and alignment you can add the data attributes data-position and data-alignment. The available values for position is top, bottom, left, and right; with bottom being default. The available values for alignment are start, end, and center; with center being the default.

Point

This option is related to the styling of the popup content. Specifically whether a point (aka arrow, or triangle) is attached to the popup content pointing towards the popup button. By default this option is set to false but to enable it you can add data-point="true" to the div.dcf-popup element.

Close Button

By default the only way to close a popup (besides the hover option and keyboard interactions) is to click the toggle button for the popup. Another way is by adding a button with the class dcf-btn-close-popup inside the popup content.

Keyboard interactions

The toggle button, when the user focuses on it, has the default toggle button keyboard interactions. Where enter, space will toggle the popup; and esc will collapse it.

Methods

While the popup class does not expose any methods the toggle button class does expose one method for toggling, opening, and closing the fieldset. The toggleSwitched method handles all three actions which seemed like a good idea at the time but feels like a bad decision now. By passing no value the toggle button will toggle, or by passing in the string 'open' or 'close' it will do the respective action. That toggle button class instance is accessible through the property toggleButtonObj.

import { getClassInstance } from '/wdn/templates_6.1/lib/unl-utility';
const popupClass = await getClassInstance('test');
// You could also use window.UNL.classes['test'] once the class is initialized
// Open and close the fieldset
popupClass.toggleButtonObj.toggleSwitched('open');
popupClass.toggleButtonObj.toggleSwitched('close');
// Toggle fieldset
popupClass.toggleButtonObj.toggleSwitched();

Events

The popup component dispatches a few events. When the class is finished initializing it will dispatch popupReady and UNLClassReady.

// Listening for class to be ready
document.getElementById('test').addEventListener('popupReady', (e) => {
  console.log('Event Name: popupReady', e);
});
document.getElementById('test').addEventListener('UNLClassReady', (e) => {
  console.log('Event Name: UNLClassReady', e);
});

Since this component uses the toggle buttons under the hood we also get access to all the toggle button events. The button in the figure is the toggle button and the toggle element is the <figcaption> element. So there are 4 events for toggling the fieldset open and closes those 4 events dispatched from the button and the figcaption: toggleButtonOn, toggleButtonOff, toggleElementOn, toggleElementOff. The toggle button and toggle element also listen for 3 command events to trigger specific actions in the component: commandOpen, commandClose, and commandToggle.

// Listening for button to be toggled to open
document.querySelector('#test button.dcf-btn-toggle-popup').addEventListener('toggleButtonOn', (e) => {
  console.log('Event Name: toggleButtonOn', e);
})
// Toggle the popup content open or closed
document.querySelector('#test .dcf-popup-content').dispatchEvent(new CustomEvent('commandToggle'));

You can also use the plugin/auto-loader events to catch when the plugin/element is loaded.

document.addEventListener('UNLPluginInitialized', (e) => {
  console.log('Event Name: UNLPluginInitialized', e);
});
document.addEventListener('UNLPluginLoadedElement', (e) => {
  console.log('Event Name: UNLPluginLoadedElement', e);
});
window.UNL.autoLoader.config.plugins.UNLPopup.onPluginLoadedElement = (loaded_element) => {
  console.log('Auto Loader onPluginLoadedElement:', loaded_element);
}
