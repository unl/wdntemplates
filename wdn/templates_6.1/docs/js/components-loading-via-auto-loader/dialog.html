Dialog - Auto-Loader

The dialog is an essential part of the framework. The dialog component (often referred to as a modal) is an interactive overlay window that layers over the main page content to capture a user's immediate attention. It temporarily halts interaction with the rest of the application, requiring users to either complete a specific task—such as confirming a critical action, filling out a brief form, or acknowledging important alerts—or explicitly dismiss the overlay.

Warning! This component is needed for the base page templates so if the primary navigation, search widget, or login widget's are not working correctly you may have changed the default dialog component configuration in the auto-loader.

This component inherits a lot of it's functionality and keyboard interactions from the browser's implementation of the dialog element.

The auto-loader references /wdn/templates_6.1/js/plugins/plugin.dialog.js by default. That plugin will be looking for .dcf-dialog:not(.dcf-dialog-initialized) as the trigger to load the components code dependencies and initialize the component.

Dialog Heading

Dialog Contents

To create the component you can add the class dcf-dialog onto a dialog element. This will make a the dialog itself but you will need a button to open that dialog. For that you will need a button element with the dcf-btn-toggle-dialog class on it. You can have multiple dialogs on a page so you need to tell the button which dialog it toggles and for that you need to add the attribute data-controls to the button whose value is the ID of the dialog you want to toggle.

You will also want to disable the button since it will not work before the Javascript has been ran. Once the dialog component has been initialized it will remove the disabled attribute from the button. 

                <button id="test-button" class="dcf-btn dcf-btn-primary dcf-btn-toggle-dialog" data-controls="test" disabled>Dialog Toggle</button>
                <dialog id="test" class="dcf-dialog">
                    <div class="dcf-dialog-header">
                        <h2>Dialog Heading
                        <button class="dcf-btn-close-dialog" autofocus>Close</button>
                    </div>
                    <div class="dcf-dialog-content">
                        <p>Dialog Contents</p>
                    </div>
                </dialog>

The dialog element will need an ID so that the toggle buttons have something to reference. The component will throw an error if the ID is missing. If the dialog toggle buttons the fieldset do not have ID then a randomly generated one will be assigned to them. Once initialized the class dcf-dialog-initialized will be added to the dialog element and it will remove the hidden attribute from the it. The class will also add itself to the window.UNL.classes object so you can use getClassInstance to get a reference of the class instance.

When the dialog is open there will be the class dcf-dialog-is-open add to the dialog element as well as the toggle buttons. When the dialog is closed that class will be removed.

Options

The dialog component has a couple options associated with it's functionality.

Confirm Close

The first options is confirm close. This will show an alert which needs to be confirmed before the dialog is closed. To add this option to your dialog you can add the data-confirmClose attribute to the dialog and it's value is the text inside the alert.

Dialog Confirm Close

Dialog Contents

 
                <dialog id="confirm-close" class="dcf-dialog" data-confirmClose="Are you sure you want to close the dialog?">
                    <div class="dcf-dialog-header">
                        <h2>Dialog Confirm Close
                        <button class="dcf-btn-close-dialog" autofocus>Close</button>
                    </div>
                    <div class="dcf-dialog-content">
                        <p>Dialog Contents</p>
                    </div>
                </dialog>

Deliberate Close

The deliberate close option changes the dialog functionality of how it closes. By default the dialog can be closed by either clicking the close button or clicking the darkened overlay behind the dialog. This option will disable the ability to click the overlay to close the dialog and force the person to click the close button. To add this option to your dialog you can add data-deliberateCloseOnly as an attribute to the dialog element.

Dialog Deliberate Close

Dialog Contents

 
                <dialog id="deliberate-close" class="dcf-dialog" data-deliberateCloseOnly="true">
                    <div class="dcf-dialog-header">
                        <h2>Dialog Deliberate Close
                        <button class="dcf-btn-close-dialog" autofocus>Close</button>
                    </div>
                    <div class="dcf-dialog-content">
                        <p>Dialog Contents</p>
                    </div>
                </dialog>

Non-Modal

By default the dialog will open to take over the whole page. This option does the opposite and opens the dialog in the non-modal state. It will not take over the page and over cover a portion of the page content. An example of this functionality is with the primary navigation on any pages using the version 6.0 and 6.1 of the framework. To add this option to your dialog you can add the class dcf-dialog-non-modal to the dialog element.

Dialog Non-Modal

Dialog Contents

                    I added the classes `dcf-w-100%`, `unl-bg-scarlet` and `unl-cream` to make
                    the dialog a little better looking for this example
                -->
                <dialog id="non-modal" class="dcf-dialog dcf-dialog-non-modal dcf-w-100% unl-bg-scarlet unl-cream">
                    <div class="dcf-dialog-header">
                        <h2>Dialog Non-Modal
                        <button class="dcf-btn-close-dialog" autofocus>Close</button>
                    </div>
                    <div class="dcf-dialog-content">
                        <p>Dialog Contents</p>
                    </div>
                </dialog>

Disable Default Classes

This option was created to go along with the non-modal dialogs in the primary navigation. This option will cause the dialog to not get it's default classes when it builds the dialog component. This is helpful when needing to design a unique dialog which can not use any of the default classes to create it's design. To add this option to your dialog you can add data-default-classes as an attribute to the dialog element with the value false.

Dialog Disable Default Classes

Dialog Contents

 
                <dialog id="default-classes" class="dcf-dialog" data-default-classes="false">
                    <div class="dcf-dialog-header">
                        <h2>Dialog Disable Default Classes
                        <button class="dcf-btn-close-dialog" autofocus>Close</button>
                    </div>
                    <div class="dcf-dialog-content">
                        <p>Dialog Contents</p>
                    </div>
                </dialog>

Dynamic Toggle Buttons

There are some cases where you would want to have toggle buttons work even after the dialog has been initialized. You can use the dynamic toggle buttons option to listen for click events all throughout the page and if the event target is a toggle button which controls the dialog it will register the toggle event. To add this to your dialog you can add data-dynamicToggleBtns="true" as an attribute to your dialog element. 

                <dialog id="dynamic-toggles" class="dcf-dialog" data-dynamicToggleBtns="true">
                    <div class="dcf-dialog-header">
                        <h2>Dialog Dynamic Toggle Buttons
                        <button class="dcf-btn-close-dialog" autofocus>Close</button>
                    </div>
                    <div class="dcf-dialog-content">
                        <p>Dialog Contents</p>
                    </div>
                </dialog>

Keyboard interactions

When opened a dialog is open has standard keyboard interactions are defined by browser standards since this component is build around the default dialog element. The main keyboard interaction is that Esc will close the dialog.

Methods

There are a couple methods that are exposed on the dialog class. close, open, and toggle. These methods do what you expect. 

                import { getClassInstance } from '/wdn/templates_6.1/lib/unl-utility';

                const dialogClass = await getClassInstance('test');
                // You could also use window.UNL.classes['test'] once the class is initialized

                // Opening, Closing, and Toggling the dialog component
                dialogClass.open();
                dialogClass.close();
                dialogClass.toggle();

Events

The dialog component dispatches a few events. When the class is finished initializing it will dispatch dialogReady (from the dialog element) and UNLClassReady (from the dialog element and the toggle buttons). 

                // Listening for class to be ready
                document.getElementById('test').addEventListener('dialogReady', (e) => {
                    console.log('Event Name: dialogReady', e);
                });
                document.getElementById('test').addEventListener('UNLClassReady', (e) => {
                    console.log('Event Name: UNLClassReady', e);
                });

There are events that are fired before and after the dialog element has opened and closed. These events are dialogPreOpen, dialogPostOpen, dialogPreClose, and dialogPostClose. This are dispatched from the dialog element.

These events also have a detail property in the event object which includes information about what type of input triggered the dialog to open/close and if it was a button which button caused the dialog to open/close. 

                // Listening for dialog to open and close
                document.getElementById('test').addEventListener('dialogPreOpen', (e) => {
                    console.log('Event Name: dialogPreOpen', e);
                    console.log('Event Details:', e.detail);
                });
                document.getElementById('test').addEventListener('dialogPreClose', (e) => {
                    console.log('Event Name: dialogPreClose', e);
                    console.log('Event Details:', e.detail);
                });

There are also events that the dialog listens for which can be used to perform actions on the dialog similar to calling the exposed methods. These events would be dispatched onto the dialog element and are commandClose, commandOpen, and commandToggle. 

                // Opening and closing dialog via event dispatch
                document.getElementById('test').dispatchEvent(new CustomEvent('commandOpen'));
                document.getElementById('test').dispatchEvent(new CustomEvent('commandClose'));

You can also use the plugin/auto-loader events to catch when the plugin/element is loaded. 

                document.addEventListener('UNLPluginInitialized', (e) => {
                    console.log('Event Name: UNLPluginInitialized', e);
                });
                document.addEventListener('UNLPluginLoadedElement', (e) => {
                    console.log('Event Name: UNLPluginLoadedElement', e);
                });
                window.UNL.autoLoader.config.plugins.UNLDialog.onPluginLoadedElement = (loaded_element) => {
                    console.log('Auto Loader onPluginLoadedElement:', loaded_element);
                }

MediaHub and Video Interaction

MediaHub videos as well as normal video elements can be set up to automatically play when the dialog is opened. For MediaHub video embeds you can add allow="autoplay" as an attribute of the iframe element. For normal video elements you can add data-autoplay="true" as an attribute to the video element. Note: if you open the dialog before the video/MediaHub embed has finished loading then the video may not play when the dialog is opened.

Dialog MediaHub Embed

Dialog Video

                        <h2>Dialog MediaHub Embed</h2>

                    </div>

                                src="https://mediahub.unl.edu/media/24339?format=iframe&autoplay=0"
                                title="Video Player: UNL CMS Training March 18"
                                allow="autoplay"
                                allowfullscreen
                            ></iframe>
                        </div>
