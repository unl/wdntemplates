Using The Framework

The UNL WDN framework is a collection of HTML page templates, HTML includes which are used in the page templates, CSS class based styles, and prebuilt JS components.

Architecture & Core Concepts

Digital Campus Framework (DCF)

The UNL WDN framework extends the functionality of the digital campus framework and adds all the UNL specific styles to it.

Digital campus framework is like the skeleton of the framework and we are adding our UNL brand identity to it. Digital campus framework includes things like basic CSS and JS. This modular approach works well when we need to switch a site's theme between different campuses such as UNL to UNMC. Keeping the structure of the site the same but swapping out themes makes this process a lot easier.

Versioning & Release Cycle

The framework follows standard Semantic Versioning (MAJOR.MINOR.PATCH) conventions:

  • Major versions: Reserved for fundamental, breaking changes and are rare.
  • Minor versions: Introduced when structural modifications are made to the base page templates.
  • Patch versions: Released monthly following the WDN meeting. These contain iterative updates to HTML includes, CSS, or JavaScript.

Although patch version are typically scheduled to be released once a month you should aim to update your framework version daily to always catch any emergency patches that may be deployed to fix major bugs. With each patch version the prebuilt framework files will include the new patch version in any CSS and JS file paths to bust the cache.

Templates & File Structure

HTML page templates come in a variety of formats to fit most people's needs. Including PHP, Twig, JSP, and Dreamweaver templates. We also support a few other libraries for integrating these page templates into your apps (phpunltemplates, wdn-symfony-framework, etc).

Includes & Editable Regions

The core philosophy is that your web application is built around the page template, which then references various global include files. These includes construct major layout pieces like the primary navigation and footer.

Your unique application content sits nestled between these fragments, wrapped inside TemplateBeginEditable and InstanceEndEditable blocks. These editable markers allow legacy environments like Dreamweaver to safely know where user content belongs.

Some include files are designed to be placeholders and live under /wdn/templates_6.1/includes/local. These are included as starter examples for local sections and can be safely swapped out with your own custom HTML content.

Hosting & Asset Delivery

By default, the framework expects CSS and JS assets to be locally accessible via a /wdn route on your web server (e.g., /wdn/templates_6.1/). If you run multiple framework versions simultaneously, they can live side-by-side in this directory. A live example of this file structure can be found at wdn.unl.edu/wdn.

Alternatively, you can also use wdn-cdn.unl.edu instead of locally hosting the framework files in case that works better for your use case. Just make sure to use a cloud template for your site instead of a local version.

CSS

The styling architecture is strictly class-based, behaving similarly to frameworks like Tailwind. Atomic CSS classes are applied directly to elements to build UI layouts.

Because we extend the Digital Campus Framework, you will notice two distinct prefixes:

  • dcf- denotes core utility and layout classes coming from the baseline framework.
  • unl- denotes design tokens and overrides specific to the UNL brand identity.

JS

Dynamic features (like slideshows or modal dialogs) rely on custom JavaScript components managed by a plugin auto-loader.

Instead of bundling all scripts into a massive payload, the auto-loader scans the DOM on page load and downloads a component's JS and CSS files only if its respective HTML markup is present on the page.

Each component is architected around a JavaScript class exposing programmatic hooks (such as open/close triggers for dialogs), combined with a plugin file that maps out dependencies and auto-load triggers.

Installation / Updating

Framework files can be consumed prebuilt from the WDN site, or compiled directly from source. Step-by-step instructions for building local environments are available in the GitHub repository README.

Updating a prebuilt installation is as simple as downloading the latest release package and overwriting your server's old directory. We strongly recommend setting up an automated cron job or deployment script to handle this step nightly. If you build from source, pull the latest changes from upstream and re-build.
